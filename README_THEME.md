# StormTwin NEXT · Professional Teal Redesign

This update keeps the original recorded SWMM simulation, Python API and pretrained ML files while reorganizing the website into six separate workspaces. It uses the light and dark HSL tokens supplied for the design, including Plus Jakarta Sans / Quicksand, teal `--primary`, chart colours, softened card borders and shadows.

## Run on Windows

1. Extract `StormTwin_Professional_Teal_Theme.zip`.
2. Open the folder `StormTwin_NEXT`.
3. Double-click **RUN_STORMTWIN_NEXT.bat** or use:

```powershell
cd StormTwin_NEXT
py -3 dashboard_server.py
```

4. Open **http://localhost:8502**.

**The new interface is HTML/CSS/JavaScript, not the legacy Streamlit `app.py`.** Python's built-in HTTP server is sufficient to display and interact with the recorded storm; no `npm install` is needed.

## Six separate workspaces

| Page | Purpose | Working controls |
| --- | --- | --- |
| **Overview** | Mission snapshot, key values, clear entry points | Workspace navigation; dynamic storm stage based on current playback minute |
| **Network Twin** | Animated drainage network and storm replay | Play, pause, speed, timeline, ±5-minute steps, hide/show rain and labels, clickable pipes, asset dropdown, inspector, collapsible advanced analysis |
| **IoT Monitoring** | Inspect the real gateway-exported synthetic telemetry | Filter by water level / flow / rainfall, select any of 15 channels, inspect quality, RSSI and battery, view its recorded trace |
| **Mitigation Lab** | Compare flood-control actions separately from telemetry monitoring | C3 restriction slider, rainfall factor, response-delay inputs, five strategy cards, animated illustrative before/after diagram, optional full PySWMM recalculation, collapsible detailed forecast |
| **AI Diagnostics** | Explain what the predictive ML and twin methods actually do | Read synthetic evaluation results, current J3 and C3 measurements and honest method caveats |
| **System Design** | Trace each actual software module | Click the architecture steps to reveal original source files and responsibilities |

### Appearance

The **Dark / Light** control is at the top-right. Your choice is retained in your browser (local storage). The default appearance is the supplied light teal style. Styles are defined in `web/assets/theme.css` and override legacy styles in `web/assets/styles.css` without deleting the prior components.

### What is simulated versus computed?

- **Recorded playback:** real values stored in the supplied `stormtwin.db`, originally generated by virtual sensors and gateway validation against SWMM, not field sensors.
- **Animated city map and water illustration:** schematic visualization; the positions and flow animation are illustrative.
- **Default T+60 intervention results:** historic reference values from the supplied project demo, not live predictions.
- **Changed parameters:** the illustration reacts immediately but forecast numbers remain visibly labelled *reference only* until actual SWMM is run.
- **Calculate with real SWMM:** calls `/api/swmm`, which uses the project's preserved `twin.py`, `demo.py`, `swmm_model.py` and PySWMM. Additional requirements must be installed:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install "scikit-learn==1.8.0"
python dashboard_server.py
```

The what-if weather uses the existing scripted future-storm data multiplied by the rainfall factor. Do not describe it as a real weather-service forecast. The project does **not** control real pumps, streets, or ESP32 devices.
